# 餐飲個店創業前財務風險評估

輸入一份餐飲創業計畫，系統以現金基礎（不攤提啟動資金）計算月損益、營業淨利（折舊前）、營業淨利率（折舊前）、經濟淨利、損益平衡營業額、安全邊際、SPLH 區間與含養店期的回本月數，並與經濟部餐飲業產業數據比較，依三項檢查給出結論：不可行／不建議／可行，但獲利偏低／可行。

- 營業淨利（折舊前）= 營業額 − 變動成本 − 人事 − 租金 − 水電瓦斯與其他，不攤提啟動資金。
- 經濟淨利 = 營業淨利（折舊前）− 老闆去上班的月薪 − 啟動資金 × 年利率 ÷ 12；大於 0 代表開店比去上班划算。
- SPLH（每工時營業額）= 營業額 ÷ 總工時（員工＋老闆）。

程式碼：<https://github.com/GuanYingLin/catering-startup-risk>

## 畫面說明

**側欄**

- 最上方「案例」選單：選「作者門市（2025/04–2026/03）」會載入作者門市的實際數字；選「自行輸入」會清空所有欄位。載入後仍可修改任何欄位。
- A–F 六個區塊依序填寫營收、變動成本、人力（只填員工）、固定費用、投資、養店期；進階設定可調整利率與法定負擔倍數。

**主畫面上半段「重點摘要」**

- 結論一行與三項檢查：

  | 檢查項目 | 標準 |
  | --- | --- |
  | ① 營運是否賺錢 | 穩定期營業淨利（折舊前）大於 0 |
  | ② 能否在租約內回本 | 含養店期回本月數不超過租約月數（租約未填則略過） |
  | ③ 獲利是否達業界水準 | 營業淨利率（折舊前）不低於該業別產業營業淨利率（折舊前）歷年最低值 |

  結論規則：第 1 項未通過為「不可行」；第 1 項通過、第 2 項未通過為「不建議」；只有第 3 項未通過為「可行，但獲利偏低」；全部通過為「可行」。

- 三句白話重點（依計算結果自動產生）：獲利與回本、SPLH 落在哪個區間、與產業平均差距最大的成本項目。
- 成本結構與產業平均的長條圖。

**主畫面下半段「計算依據」**：計算明細（營業額、變動成本、人事、固定成本、機會成本、SPLH 四個門檻的算式與代入值）、月損益表、成本結構明細、SPLH 區間、養店期逐月表、營業額下滑情境與風險說明、假設與資料來源。

**自行輸入模式**：主畫面列出「最少要填」清單，填好的項目會打勾；關鍵欄位的問號有說明與產業參考值。

**頁尾**：作者、GitHub 連結、資料更新日期與免責聲明。

## 本地執行

```bash
pip install -r requirements.txt
streamlit run app.py
```

瀏覽器會開啟 http://localhost:8501 。

## 測試

```bash
pip install -r requirements-dev.txt
python -m pytest
```

`tests/test_engine.py` 檢查作者門市的驗收數字（營業淨利 69,132 元、含養店期回本 19.4 個月、經濟淨利 19,857 元等）、四種結論、三句重點與極端輸入。

## 檔案

| 檔案 | 內容 |
| --- | --- |
| `engine.py` | 計算引擎與判斷規則（不含畫面）；產業基準值、法規參數、假設與資料來源表、案例都在這裡 |
| `app.py` | Streamlit 畫面 |
| `tests/test_engine.py` | 計算引擎的測試 |
| `requirements.txt` | 執行所需套件 |
| `requirements-dev.txt` | 測試所需套件 |
| `.gitignore` | 不納入版本控制的檔案 |

新增案例：在 `engine.py` 定義一個 dict（欄位同 `Plan`），加進 `CASES` 即可，畫面不用改。

## 部署到 Streamlit Community Cloud

1. 到 share.streamlit.io，用 GitHub 帳號登入，按 **Create app**。
2. 儲存庫選 `GuanYingLin/catering-startup-risk`，分支選 `main`，主檔案填 `app.py`，按 **Deploy**。
3. 之後推送到 `main` 的修改會自動更新到網站。
